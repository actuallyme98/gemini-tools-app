# Routes, loading and controls

Creative Studio uses React Router in declarative browser-history mode. Each main screen has an actual path, so refresh, deep links and Back/Forward work without the old hash navigation. Nginx already serves the SPA entry point for these paths.

| Screen | Route |
| --- | --- |
| Overview | `/` |
| Idea Board / create / detail / edit | `/ideas`, `/ideas/new`, `/ideas/:id`, `/ideas/:id/edit` |
| Gallery / selected idea | `/gallery`, `/gallery/:id` |
| Mockup creation / results | `/mockups`, `/mockups/:id` |
| Approved output | `/outputs` |
| Teams / stores / library | `/manage/teams`, `/manage/stores`, `/manage/library` |
| Team budget / schedule operations | `/manage/budgets`, `/manage/schedule` |
| Administration | `/admin`, `/admin/users`, `/admin/jobs`, `/admin/audit`, `/admin/settings` |
| Guide | `/guide` |

Legacy `/#studio-*` and `/#admin-*` links are replaced with the equivalent paths, preserving draft/result IDs and mockup handoff parameters. Resource type is a query filter, for example `/manage/library?type=thumbnail`. Management tabs update the route. Authentication stays mounted across client navigation; permissions are enforced again by the API.

Redux is not required for the current state flow. URL parameters own navigation, existing React state owns form edits, the existing provider context owns model selection, and the API owns persisted drafts/jobs. There is no duplicate global copy of server records or session tokens.

`StudioSkeleton` reserves space for list, form, dashboard, gallery, table and session loading. It announces loading once, hides decorative placeholders from assistive technology and disables shimmer for reduced-motion users. Existing content stays mounted during library refresh to preserve open version/context panels.

`StudioSelect` uses the installed Radix Select primitive: portaled collision-aware options, icons, selected checkmark, typeahead/arrow navigation, Escape and focus return. A visually hidden native select preserves form fields and required validation; failure focuses the visible trigger and displays an error. Native inputs for dates/numbers remain native.

Only the application role `admin` may create/submit an idea with automatic scheduling, approve a scheduled idea, configure the schedule or run catch-up operations. Team Leader membership alone does not grant scheduling access. Worker permission checks block scheduled work when owner/approver loses admin access. Immediate jobs retain the normal Seller/Leader review flow. The scheduler feature flag is still an independent server setting; this code change does not enable it.

Validation uses mocked provider transports; no paid image request is required for these UI/permission checks. Preview artifacts are generated by Playwright under ignored `test-results/`.

Validation checkpoint: frontend lint/build and all 47 Playwright scenarios pass. API lint/build, 31 Studio integration cases and 2 real Redis/Mongo queue cases pass; provider transports are mocked. Production dependencies report zero audit vulnerabilities. The changes are local and have not been committed or deployed.

Mockup creation keeps the three desktop columns and lets their full content determine page height. Sources, scenes and review controls use the document scroll rather than independent panel scrollbars; mobile retains the stacked layout.

Artwork review now explicitly asks reviewers to reject product silhouettes, stitching, physical shadows and external white margins; dimensions/DPI alone are not visual acceptance. The API prompt changes apply to new slots only, and need real-provider visual revalidation.
